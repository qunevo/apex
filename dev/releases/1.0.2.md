# APEX 1.0.2

## Changes

- Fix the demo's Open in Excel action when an earlier starter created its shared
  desktop bridge as root. Initialization now uses the configured container user
  and repairs the bridge directory ownership without replacing the workbook.
- Keep the synthetic demo at October 5, 2026, 10:00 Europe/Berlin. The MES shows
  the fixed snapshot and rejects attempts to advance it. Order, receipt,
  calendar and Excel dates do not move with the computer's current date.
- Carry the frozen snapshot through chat onboarding, adapter assumptions,
  import reports and persisted scenario source views. Distinguish work already
  overdue at that snapshot from predicted lateness in a validated future plan.

## Compatibility and upgrade

The scheduling input contract and engine semantics are unchanged. Rebuild the
demo containers with the normal starter and resume existing data to apply the
fixes. Credentials, MES edits, saved workbooks and APEX plans are retained.

The optional demo's clock control is intentionally read-only; POST /api/clock
now returns HTTP 409. A previously advanced saved snapshot is preserved, not
silently reset. Existing imported scenarios also retain their original evidence;
new imports and updated chat instructions carry the explicit frozen time basis.

Sequence-dependent setup matrices and workplan-navigation changes are not
included. The full-factory acceptance case explicitly extends the planning
horizon to October 30, 2026 and uses the release construction strategy. This
does not change the demo's October 5 snapshot or its October 16 source horizon,
and does not claim feasibility under the original horizon or optimality.

## Validation

The reviewed feature revision passed CI on Linux, Windows and macOS, including
Rust linting, tests and release builds, real-engine adapter validation, MCP/HTTP
and viewer integration, standalone source-distribution checks, PostgreSQL
conformance and publication checks. The container acceptance test imports all
3,705 unfinished demo operations from MES and saved Excel, plans them and checks
the independently validated MCP result and source views. It also verifies frozen
time after import, service recreation and reset, Excel bridge ownership, workbook
persistence and retained access tokens. Local checks additionally passed 55 MES
tests, 54 contributor tests and locale consistency checks. The versioned release
candidate must pass the same required CI gate before merging.
