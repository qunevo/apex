# APEX 0.2: relationships, customization, agent access and UI

23 September 2026. Rust engine 0.2.0, executable schema `apex.v3.2`. This extends the 0.1 implementation in response to the [v2 source audit](v2-parity-audit.md). Tests use deliberately synthetic data. No solver, RL model, live ERP or LLM API is involved.

## What changed

| Area | Delivered behavior | Evidence |
| --- | --- | --- |
| Workplans | Whole-route choices control active tasks, dependencies and material flows; explicit/pinned choices and locks remain consistent | `tests/parity.rs`, HTTP route-change workflow |
| Conditional work | Task- and main-mode-specific pre/post DAGs, parallel branches, joins, temporal lags and resource association | Parallel-preparation and independent-inspection tests |
| Production structure | Templates expand quantities into lots, jobs, orders and selectable routes; fixed/per-unit work and per-unit template materials | Expansion/remainder/order-dependency tests and production fixture |
| Objective meaning | Product readiness aggregated by job/order, separate tardiness metrics, independent setup penalty | Corrupted completion/penalty tests |
| Sequence customization | Family suffix patterns and complete selected resource-sequence hooks add activities/penalties | Sequence tests and native activity replay test |
| Native policies | Model lowering, dispatch adjustment, custom metrics and hard validation; linked ID/version registry | Native policy rejection and corrupted-result tests |
| Freeze policy | Resource cutoffs override global cutoff before baseline membership is selected | Service override test plus existing lock/running-work tests |
| Agent interface | 25 tools over stdio MCP, Streamable HTTP and plain JSON HTTP; generated OpenAPI, bearer authentication, remotely pageable artifacts | Official SDK tests for both transports |
| Workbench | Resource occupancy, active-operation counts, job/order deadlines, route pinning, task details, rules/locks, scenario comparison, outage form and shareable views | Browser workflow and screenshots |

The same hard constraints and independent validation apply to Fast Planner and trainer. Trainer searches for a better valid plan; it is not a substitute for validation. New attribute objectives derive their dispatch signal from the typed declaration. Arbitrary new native objectives still need deliberate heuristic design and tests.

## Qualitative outcomes

1. **Scenario tradeoffs remain visible.** The HTTP client pinned the first lot to its other workplan, causing two operations to be replaced. Mode cost fell from 400 to 340; order-weighted tardiness rose from 490 to 875 and makespan from 2,945 to 3,030 seconds. A valid alternative is not automatically a better alternative under the selected objective.
2. **Trainer can improve a real combination of constraints.** In the 16-operation shift fixture, weighted tardiness fell from 7,950 to 2,320 (70.8%), makespan from 5,250 to 4,890 seconds, and conditional work from 1,080 to 720 normalized seconds. Both results passed independent validation.
3. **Improvement is not guaranteed.** The three-order fixture and scaled production fixtures retained the initial solution within the tested budgets. The 100,000-task simple case improved its primary tardiness objective by about 8.7%, while makespan increased because makespan was secondary. Report the complete objective vector, not just one favorable KPI.
4. **Custom rules are enforced beyond construction.** A native sequence hook adds real conditional inspection work. Removing that work from the saved result fails validation. A rejecting custom hard policy rejects Fast Planner, trainer and saved-result validation. Altered route decisions, activity modes, completion aggregates and penalties are also rejected.
5. **Resource release is distinct from product release.** Long inspection on another resource delays product readiness but does not prevent a successor from using the original machine after it is free.
6. **Large input does not need to fill the model context.** Durable chunks, source references, bounded pages and remote artifact traversal provide a file/converter workflow. This still requires an agent host to run or access the converter and transfer artifacts appropriately.

## Remaining acceptance work

The audit's principal model gaps now have executable representations and synthetic interaction tests. **This is not proof of lossless v2 replacement.** A raw v2 input adapter and equivalent end-to-end runs of representative legacy cases remain necessary. Private sequence callbacks, custom KPIs, BOM/supply allocation and preparation policies require explicit ports and acceptance examples.

Conditional graphs are scoped to pre/post stages; arbitrary cross-task internal activity endpoints and nested conditional graphs are not supported. Dynamic worker replacement, arbitrary preemption, simultaneous production batches and stochastic simulation remain outside the executable contract. Unsupported nested conditional semantics are rejected rather than ignored.

Repair is a full reconstruction. Search is heuristic, time budgets are soft between evaluations, and failure is not an infeasibility proof. Native extensions are statically linked and require a rebuild. The service is synchronous and uses a single-workspace filesystem store, with no built-in OAuth, TLS or tenant separation. No external solver is connected. Publication/licensing preparation is a separate existing workstream; this report does not declare the checkout ready for distribution.
