# APEX 0.4.1: combined improvement acceptance report

24 September 2026. Synthetic data only. [Implemented contract and modeling trade-offs](../architecture/combined-improvement.md).

## Result

- `schedule.improve` combines Trainer and Plus under one evaluation/time allowance. The normal planning contract is Quick plan / Improve plan; standalone search tools remain available for diagnostics.
- 107 Rust tests pass (97 previous + 10 additional); formatting, Clippy with warnings denied, official MCP SDK, HTTP and browser workflows are checked separately below.
- Same nominal time budgets: **612 search runs**, 34 model/budget groups. Compared with the better standalone result: **14 better / 170 equal / 20 worse; 0 unavailable**.
- New release-time validation cases (not used to introduce the reference-policy anchor): **12 better / 60 equal / 0 worse; 0 unavailable**.
- At the requested deadline, using recorded incumbent availability: **14 better / 164 equal / 20 worse; 6 unavailable**. Unavailable means the combined run or both standalone runs had no recorded valid incumbent by that checkpoint; it is not a tie or pass.
- Fixed evaluation allowance: **9 better / 19 equal / 23 worse; 0 unavailable**, across 153 runs. Every run honors the total cap and retains a score no worse than its own initial constructive result.
- These results do not establish universal superiority over either standalone method, mathematical solvers, or optimality. The full measured comparison includes losses; the combined method is a usable portfolio, not a proven best algorithm for every instance.

## Reproducibility and fairness

Windows 11 / Intel Core Ultra 9 275HX; Rust 1.98.1, optimized release, one search worker, population 4. Time budgets are 100 and 500 ms; seeds 19, 42, 73; two repetitions. One warmup per model/method is excluded; method order rotates. No other test/build workload was intentionally run during timing. The nominal budget is shared, not granted in full to each phase.

Final executable SHA-256: `75b12c07b13c76ca47bdf875d7f70a37cd741308e722bd417360656f1c7e8488`.

The models include small weighted-completion problems with release times, shifts/materials/conditionals, campaign policies, expanded production/routes and 256/1,024-operation multi-mode problems. Small release cases have independently enumerated optima; no industrial optimality claim follows. The initial six cases informed the anchor correction; six new cases were then added for validation. This remains a small synthetic sample, not a certified generalization test.

Elapsed time includes construction and independent validation; the combined outer timer also includes normalization and handoff. CLI wall time additionally includes startup, parsing and serialization. Timers are soft: a complete evaluation, expansion or worker batch may finish after the deadline. Raw data preserves wall time, peak RSS, evaluation counts, phases, final scores and bounded incumbent curves.

## An adverse design result and its correction

The first implementation retained only the best distinct training policies. Across the original 11 models (before adding six new validation cases), its comparison against the better standalone result was **4 better / 99 equal / 29 worse; 0 unavailable**. In particular, a better greedy score sometimes removed the original Q policy even though that policy gave Plus better exploration opportunities. [Preserved initial experiment](v0.4.1-improve-initial-measurements.json).

The final implementation reserves one of multiple policy slots for the first valid Q policy and uses the remaining slots for evolved elites. The anchor is explored first. This is a deliberate search-diversity rule, not an automatically learned allocator. It can still lose to a standalone method because that method gets the entire budget. Structural Q diversity does not guarantee behavioral diversity.

## Existing-core regression

The preserved 0.4 binary was compared with 0.4.1 on unchanged and declaratively equivalent inputs with 12 evaluations. **18/18 groups preserve quality**; **18/18 meet the 5% paired-median runtime margin.** This engineering tolerance is not a statistical non-inferiority certificate. [Raw paired regression](v0.4.1-core-regression.json).

## Verification and limitations

- Semantic tests cover shared budgets down to one evaluation, distinct handoffs and the reference anchor, genuine mutation/crossover, deterministic replay, incumbents, corrupted scores, changed scenario revisions, native hooks, exact campaign policies, fixed starts, route locks, Pareto replay and multi-worker execution.
- A deliberately slow customization checks that an expired total time budget is not restarted for Plus. A failed initial Trainer population can still be recovered by prefix exploration.
- MCP and HTTP tests discover 31 tools and invoke combined improvement with a saved incumbent. Browser tests exercise Quick plan / Improve plan, phase evidence, objective changes, freezes and read-oriented viewing.
- [MCP verification: six workflows](v0.4.1-agent-workflows.json), [HTTP verification: five workflows](v0.4.1-http-workflows.json), [combined-search viewer screenshot](v0.4.1-combined-viewer.png). One unrelated opt-in Rust report test remains ignored.
- The controller is synchronous and sequential across phases. It is not an adaptive algorithm selector, resumed cross-request search or a stochastic simulator. Progress is returned after completion. No new Q formulas are synthesized.
- New rules still use typed templates or tested Rust extensions; no untested source text is executed from tool input. CP/MIP performance has not been benchmarked against equivalent full APEX semantics.
