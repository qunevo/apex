Feasibility constraint

“This schedule is allowed.” Enforce restrictions during construction and check the final schedule independently.

Construction policy

“Choose from this subset next.” Pin the rule, its scope, exceptions and fallback throughout the search.

Objective and Q proxy

“Prefer a promising choice.” Rank allowed candidates, then evaluate actual schedule metrics.

1 · Pre-migration algorithm (0.3)

Order and mode selection use estimated state. Exact decoding follows complete-sequence customization. Stateful hard candidate filtering is the missing extension point.

2 · Proposed decision loop

Structural rules arrive first. Rules requiring actual productive time need decoder-backed probes. An incomplete candidate window cannot justify a “no continuation” fallback.

3 · Shared modules and hooks

Immutable compiled rules, isolated state per evaluation, and the same checks for normal selection, training and forced-prefix replay.

4 · Domain-expert workflow

Supported parameters are configured in chat. New semantics become a versioned code change with examples, independent validation and quality evidence.

Implementation order

  1. Shared next-step contract. Unify strategies, branch enumeration and prefix replay while preserving existing behavior.
  2. Structural policy hooks. Add typed scope, candidate queries, exclusions, explicit fallbacks and decision reasons.
  3. Exact temporal rules. Reuse decoder placement, define duration bases and handle running work and sequence-dependent effects.
  4. Domain workflow. Deliver rule templates, knowledge records, chat tools, scenario comparisons and explanations.
  5. Measured quality and speed. Compare actual objectives, valid-result rates, latency and memory at equal budgets.
